# Correspondance node-api-dotnet → primitives Bun / .NET, goulots et correctifs

Références : [node-api-dotnet.md](node-api-dotnet.md) (`microsoft/node-api-dotnet@0483aa01`), [bun-lowlevel.md](bun-lowlevel.md) (`aphrody-labs/bun@4b8463ee`), [dotnet-lowlevel.md](dotnet-lowlevel.md) (`dotnet/runtime@42656136`, .NET 11.0.0 GA 2026-11-10). Node pour comparaison : `nodejs/node@67e45e4a87` (main, 2026-11-12, lu via gh api). Préfixes : `nad:` node-api-dotnet, `bun:` fork Bun, `rt:` dotnet/runtime, `node:` nodejs/node.

## 1. Trois voies

| Voie | Principe | État |
|---|---|---|
| A. Addon Node-API (aujourd'hui) | `.node` NativeAOT de node-api-dotnet chargé par `process.dlopen` de Bun | Structurellement compatible : les 140 symboles importés sont définis et exportés par `bun.exe` ; TSFN présente. Jamais testé sous Bun (CI `nad:.github/workflows/build.yml:15-16` = Node seulement) |
| B. bun:ffi direct (cible « natif ») | Bibliothèque NativeAOT `NativeLib=Shared` exportant des `[UnmanagedCallersOnly(EntryPoint)]` blittables, ouverte par `dlopen` de `bun:ffi` | Aucun Node-API ni env : appels typés compilés par JSC (`bun:src/jsc/bindings/JSCFFIBridge.cpp:65-97`, moteur hors dépôt). Limité aux scalaires/pointeurs ; objets, chaînes et durées de vie à la main |
| C. Hybride | Voie B pour les chemins chauds (nombres, tampons), voie A pour les objets, classes, promesses | Recommandée : même `.dll` NativeAOT peut exporter `napi_register_module_v1` et des symboles C plats |

## 3. Goulots et limites mesurables dans le code

1. **Coût par appel Node-API, double allocation** : côté .NET une `JSValueScope` (classe) par appel + 2 `napi_get_cb_info` + 2 `SetSynchronizationContext` (`nad:JSValue.cs:1362`, `nad:src/NodeApi/JSCallbackArgs.cs:34-46`, `:75-84`, `nad:src/NodeApi/JSValueScope.cs:349-355`, `:399`) ; côté Bun une cellule GC `HandleScopeImpl` par appel et un append verrouillé par argument objet (`bun:src/jsc/bindings/napi_handle_scope.cpp:67-71`, `:121-142`, `bun:NapiClass.cpp:67`).
2. **Accès propriété par nom** : nouvelle chaîne JS + `napi_get_property` à chaque `value["x"]` (`nad:JSValue.cs:114-118`, `:560-562`) ; `node_api_create_property_key_*` de Bun ne fait pas d'atome (`bun:napi.cpp:1525-1550`).
3. **Sémantique v8 implicite** : ni le module généré ni `NativeHost` n'exportent `node_api_module_get_api_version_v1` (`nad:ModuleGenerator.cs:294-298`, `nad:NativeHost.cs:184-187`) ⇒ v8 sous Bun et Node (`bun:BunProcess.cpp:798-802`, `node:src/node_version.h:118`) : `napi_ref` refusé sur primitives (`bun:napi.cpp:1113-1118`).
4. **Équité TSFN** : file illimitée (`nad:JSSynchronizationContext.cs:267-273` `maxQueueSize: 0`) et Bun vide toute la file en un tick (`bun:napi_body.rs:2721-2791`) alors que Node plafonne à 1000 (`node:src/node_api.cc:409`, `:570`).
5. **Fuite à l'abort TSFN** : `CustomCallJS`/`DefaultCallJS` retournent sur `env` nul sans libérer le `GCHandle` de la donnée (`nad:src/NodeApi/Interop/JSThreadSafeFunction.cs:227-230`) ; Bun rend bien les éléments restants avec env nul (`bun:napi_body.rs:2968-2985`).
6. **Pas de net11 ni de Bun en CI** : TFMs `net10.0` max (`nad:Directory.Build.props:3-11`), SDK `10.0.303` (`nad:global.json`), runtime de test codé en dur `node --expose-gc` (`nad:test/TestBuilder.cs:306-312`, `nad:test/JSProjectTests.cs:171`). Côté Bun, pas d'addon compilé en CI Windows (`bun:test/expectations.txt:20-24`).
7. **Cycles inter-GC** : wrapper JS → `GCHandle` fort → objet .NET → `JSReference` fort → wrapper : fuite (aucun pont ; le seul pont du runtime, `JavaMarshal`, est Android : `rt:CoreLib/Java/JavaMarshal.Unsupported.cs:20`).
8. **bun:ffi** : pas de struct par valeur, pas de varargs, pas de type chaîne UTF-16, retours de `JSCallback` threadsafe non spécifiés, `ptr`/`read.*` sans intrinsic (`bun:abi_type.rs:15-49`, `bun:ffi_body.rs:1844-1963`, `bun:src/jsc/bindings/ZigGeneratedCode.cpp:9-28`) ; types et appel dans le WebKit précompilé (`bun:scripts/build/deps/webkit.ts:4-6`).
9. **Découverte hostfxr maison** (`nad:src/NodeApi/DotNetHost/HostFxr.cs:56-70`, TODO de porter `nethost.cpp`) au lieu de `get_hostfxr_path` (`rt:src/native/corehost/nethost/nethost.h:91-94`).
